# 옵티

넥슨(한국), 블리자드(아시아·아메리카·유럽), 넷이즈(중국) 공식 영웅 통계(경쟁전 역할 고정, PC)로 계산한 오버워치 메타 지수와 티어 사이트입니다. 중국은 맵별 수치를 공개하지 않아 전체 맵 티어만 제공합니다.

- **한눈에 보기**: 왼쪽은 영웅 티어(요약·돌격·공격·지원), 오른쪽은 맵별 메타(맵마다 돌격 1·공격 2·지원 2와 예비 2명).
- **맵·영웅 상세**: 맵별 티어표, 영웅 추이, 메타 지도, 세부 수치, 맵별 티어 비교. 표본 보정과 지수 가중치를 바꿀 수 있습니다.
- **랭크 구간**: 기본은 마스터~챔피언이고, 브론즈부터 챔피언까지 아무 연속 범위나 고를 수 있습니다. 공식 통계가 그랜드마스터와 챔피언을 함께 집계하므로 등급은 8개, 범위는 36가지이고, 범위마다 같은 방식으로 따로 계산합니다.

## 동작 방식

- `index.html`: 사이트 페이지. 열 때 `data/`에서 서버 정보와 고른 랭크 범위의 계산 결과를 불러옵니다.
- `refresh.py`: 다섯 서버 × (8개 등급 + 전체 티어) × 전체 맵·맵별 공식 통계 약 1,400개 화면을 수집해 다시 계산합니다. 파이썬 표준 라이브러리와 `curl`만 씁니다.
  - `data/index.json`, `data/<서버>.json`: 서버 목록, 영웅·맵 목록
  - `data/<서버>/<범위>.json`: 랭크 범위별 계산 결과. 범위 id는 모든 랭크면 `all`, 아니면 `<낮은 등급>-<높은 등급>`(0 브론즈 … 7 그랜드마스터·챔피언)
  - `history/<서버>.json`: 수치가 바뀔 때마다 남기는 기록(최근 40개). 티어 변동 비교와 패치 감지에 씁니다.
  - `archive/<서버>/<범위>.json`, `archive/<서버>/meta.json`: 하루 한 번(한국 시각, 그날 마지막 수치) 저장하는 범위별 전체 맵 기록. 영웅 추이 그래프가 읽습니다.
- `.github/workflows/refresh.yml`: 6시간마다(그리고 화면·계산 코드를 바꿀 때마다) `refresh.py`를 실행합니다. `history/`, `archive/`, `meta/`는 커밋하고, 사이트는 이 작업이 GitHub Pages로 배포합니다. 화면용 `data/`는 저장소에 쌓지 않습니다(배포할 때 지금 사이트의 데이터를 받아 와서 이어 계산).
  45일 동안 커밋이 없으면 예약 실행이 멈추지 않도록 빈 커밋을 남깁니다.
- `tools/pull_live.py`: 지금 사이트가 배포 중인 `data/`를 내려받습니다(워크플로가 씀).
- `tools/patches.py`: 블리자드 패치 노트(한국어)를 읽어 영웅별 변경 문장을 버프(▲)·너프(▼)·판단 보류(•)로 나누고 `meta/patches/<연도>.json`(목록은 `meta/patches/index.json`)에 저장합니다. 2016년 오버워치 1 패치 노트부터 들어 있고, 한국어 페이지가 없는 달은 영어 페이지를 읽습니다. 사이트의 '패치 노트' 화면이 읽습니다. 자동 분류가 틀렸으면 `meta/patch-overrides.json`에 `{"<패치 id>": {"<영웅 id>": "buff|nerf|mixed|rework|change"}}`로 고쳐 둡니다.
- `tools/weights.py`: 기본 가중치를 '개발진 판단과의 일치'로 정하고 `meta/weights.json`에 저장합니다. 패치 직전 지수에서 그 패치로 너프될 영웅은 높고 버프될 영웅은 낮게 나오는 가중치를 찾습니다(1% 단위, 각 10~70%, 패치를 하나씩 뺀 결과의 중간값, 한 번에 각 10%p 이내). 출발 자료는 `meta/judgment-base.json`(영웅별 밴률이 공개된 2026년 2월 이후 모든 패치의 패치 직전 공식 통계와 확실한 버프·너프, 블리자드 서버는 github.com/hermit-crab/ow-winrates-faceted 의 시즌별 저장본)이고, 이후 패치는 `archive/`로 더합니다. 패치 후 9일이 지나면 반영합니다. `refresh.py`와 사이트가 이 값을 기본값으로 씁니다.
- `assets/opti-icon.svg`: 파비콘. `assets/ranks/`: 오버워치 공식 경쟁전 등급 아이콘. `assets/maps/`: 맵 이미지(720×405로 줄인 공식 맵 이미지, 새 맵은 `<맵 id>.jpg`로 추가. 없으면 "이미지 없음"으로 표시). 영웅 초상화는 블리자드 공식 이미지 주소를 그대로 씁니다. 게임 이미지는 모두 Blizzard Entertainment의 저작물입니다.
- 글꼴: Pretendard(SIL OFL 1.1), jsDelivr CDN의 가변 다이나믹 서브셋.

## 처음 설정

1. **Settings → Actions → General → Workflow permissions**에서 **Read and write permissions**를 선택합니다.
2. **Settings → Pages → Build and deployment**에서 Source를 **GitHub Actions**로 바꿉니다.
   (아직 "Deploy from a branch"면 워크플로가 예전처럼 `data/`를 커밋해 사이트가 계속 동작하고, 설정을 바꾸면 다음 실행부터 자동으로 Actions 배포로 넘어갑니다.)
3. **Actions** 탭에서 **공식 통계 갱신 → Run workflow**로 한 번 실행해 동작을 확인합니다.

사이트 주소: https://uhye0n.github.io/opti/

## 참고

- 수집이 실패하면(공식 페이지 구조 변경 등) 워크플로가 실패로 표시되고 GitHub가 알림 메일을 보냅니다. 이때 사이트는 마지막으로 성공한 데이터를 그대로 보여줍니다.
- 로컬에서 직접 갱신: `python3 refresh.py` (변동이 없으면 아무것도 쓰지 않습니다. 강제로 다시 계산하려면 `--force`)
- 로컬에서 보기: `python3 -m http.server` 후 http://localhost:8000
